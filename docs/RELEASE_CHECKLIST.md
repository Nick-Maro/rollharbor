# First public release

The first release should make the demo easy to try and set accurate expectations.

- Review the staged source and the MIT/CC BY attribution boundaries.
- Run unit, HTTP, browser and Windows launcher checks as applicable.
- Verify first launch from a clean clone and a second launch with existing progress.
- Preview the English and Italian READMEs and their screenshots on GitHub.
- Choose the repository name and remote destination before publishing.
- Suggested description: **Local tabletop companion for four players and a chat DM. Maps, characters, combat and persistent saves. Python, no runtime dependencies.**
- Suggested topics: `tabletop`, `virtual-tabletop`, `python`, `rpg`, `dnd`, `srd`, `local-first`, `italian`.
- Release notes should link the demo, explain local-only access and name optional extras.
- Never include private campaign snapshots or commercial adventure sources.

Useful launch material: one screenshot of the atlas, one of character creation,
and a short recording of a declared action appearing on the board after a save.
Use only the original demo with fictional sample characters. Do not claim hosted
multiplayer, a built-in autonomous DM or complete rules automation.
